# 评测协议 math-answer-v1

用户题目固定后缀，要求最终一行 `答案：数值`，非整数用最简分数且不带单位。使用原模型的 chat_template，`open_thinking=False`；训练和生成共享完全相同的 assistant 空思考前缀。训练只监督该前缀之后的答案和结束标记，不监督用户题目、空思考前缀或 padding。序列过长时报错，不截断。

判分器忽略已闭合 `</think>` 之前的内容，拒绝未闭合思考。之后必须恰好出现一次 `答案：` 或 `答案:`，处于单独的最后一行。允许之前有解释文字，最终值只允许有符号整数、有限小数或分数；不接受表达式、单位、多个结论、科学计数法、NaN。用 Fraction 约分精确比较，0.5 和 1/2 相等，不用浮点容差。

默认生成 max_new_tokens=256、贪心、batch=1、KV cache 开启、不使用计算工具。开发集 64-token 试跑出现全部截断，因此在正式实验之前将预算改为 256；不能混用两种预算的结果。设备自动选 CUDA/MPS/CPU，CPU/MPS 使用 float32；正式实验必须固定。到 token 上限且最后没有 EOS 时判 truncated，即使中间出现答案也计错。解析失败、运行错误、截断始终计入全部请求题目的分母；错误保留原始输出。尚未实现逐题墙钟超时，生成由 token 上限限制。

`--limit` 的开发子集按题型名称排序后轮流取一题，保证小样本覆盖题型；不指定 limit 时按冻结文件顺序评估全部题目。实际选中的 ID 都写入 run.json。正式报告不要用小样本结果代替完整测试。

主指标为最终答案 accuracy；分别报告 task 和 distribution 的 N、accuracy、parse_failure_rate、truncation_rate、runtime_error_rate，并报告各实际题型等权宏平均。若只评估一个划分，不把它叫作完整测试结果。格式失败可能掩盖基础模型部分计算能力，应人工检查输出，但不得为提高分数事后放宽解析器。

逐题记录 sample_id、problem_key、task、template_id、distribution、标准答案、原始输出、解析答案、correct、failure_type、生成 token 和秒数。wrong_answer 只表示解析到合法值但数值不同；v1 不自动推断“计算错误”或“题意错误”，这些归因需要人工复核。

完整预热一题，不纳入延迟。每题开始/结束同步设备，端到端计时含模板和解码；P95 使用 nearest-rank。资源指标只能在相同硬件、dtype、输出预算和适配器形态下比较。

比较工具要求同一基础权重/Tokenizer、冻结数据、逐题 ID、解码、设备、dtype、判分与评测源码。按唯一问题组进行 5000 次配对 Bootstrap，报告差值百分点和百分位区间；每个问题只有一个观测。该区间不覆盖训练种子方差。修改判分器/数据/生成协议需要更新版本并重跑相关 Baseline。

补充诊断使用 `scripts/analyze_predictions.py`，不改变以上主指标。脚本核对冻结数据/manifest/判分代码哈希、预测 ID 完整性、参考身份和已解析答案；按表达式 AST 统计加、减、乘、单步除法、混合运算，以及不含任何除法的子集。失败题仍计入各自子集分母。对于单步整数除法，额外标记输出是否原样保留了两个操作数作为分子/分母；这个行为可由复制得到正确值，不能作为掌握一般计算的充分证据，也不用于取消其原有准确率得分。

2026-10-22首版交付采用提前注册的有界测试子集：ID、模板OOD、范围OOD各90题（各题型30题），共270个独立问题；并非把完整1,600题全部测完。题目ID在筛选前的 `results/evidence/2026-10-22-posttrain/plan.json` 固定。所有原始/训练模型评测同一270题，报告应称“预注册270题测试”，不得省略分母冒充全量测试。三训练种子的810条输出仍对应同一270个问题；均值和样本标准差反映这三个种子的观测波动，不是810个独立问题的置信区间。种子42在测试前固定为发布版本，不按测试结果选种子。
