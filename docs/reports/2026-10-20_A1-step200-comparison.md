# A1-200：续训至 200 次更新与完整验证对比

执行日期：2026-10-20。状态：本阶段已完成。问题：保持模型、数据和 LoRA 配置不变，只增加训练量，能否改善 50 步模型几乎不会普通计算的问题？前一阶段见 [50 步完整验证报告](2026-10-20_A1-step50-full-validation.md)。

## 1. 输入与控制条件

从 `artifacts/A1-pilot/checkpoint.pt` 的第 50 次更新恢复，额外执行 150 次，累计 200 次。使用同一个 MiniMind-3 Dense 基础模型、Tokenizer、数据 v1、样本顺序种子 42、官方 Q/O LoRA（rank=16、alpha=16、dropout=0）及原学习率 1e-4。设备仍为 Apple M4/MPS、float32。

393,216 个适配器参数参与训练，基础参数冻结。microbatch=4、累积 4 次，有效 batch=16；本阶段新增 2,400 条训练样本，累计 3,200 条，均处于第一个 epoch 内，没有跨 epoch 重复。训练池为 8,000 条，原计划为 3 epoch，本轮尚未完成原定全程。

训练程序严格核对原配置、基础权重/Tokenizer、数据、训练源码和环境身份后恢复，未编辑旧运行清单绕过检查。基础权重 SHA256 为 `3adf69402b5d22e693151cabadc12528f923c4ba6bf343738aaf13f0892162e8`；代码基于 `170d095`，工作区有未提交改动。身份细节及源码哈希见 [训练运行清单](../../results/evidence/2026-10-20-A1-step200-full/train/run.json)。

## 2. 具体执行了什么

1. 保留前一阶段的 50 步完整快照与全部 1,000 题输出，避免续训覆盖对照。
2. 使用原训练入口的 `--resume --stop-after-updates 150`，从第 51 次更新继续到第 200 次。
3. 沿用原保存/选择规则，在第 100、200 次更新计算完整 1,000 题验证 loss；best 在已验证的 step 0/50/100/200 中按最小 loss 选择。本次 best 与 last 权重哈希相同，确认选中第 200 步。
4. 将续训目录完整复制为本地 `artifacts/A1-step200/` 快照，验证适配器文件哈希及基础模型绑定。
5. 用该快照的 best 对与 50 步模型**相同的全部 1,000 道验证题**生成，保持原提示词、贪心、关闭思考、256-token 上限、batch=1 和精确有理数判分。
6. 运行运算类型分析、原有配对比较工具，并用一次性 Python 分析按子集计算配对差值和区间；检查所有非除法正确案例。
7. 归档本阶段训练/评测清单、日志、原始输出、分析和比较，更新本报告与报告索引。正式 ID/OOD 测试仍未用于生成评测或选择方案。

## 4. 实际执行命令

从仓库根目录使用 `.venv/bin/python`：

```bash
python -m mathlab.train --config configs/official_lora.json \
  --out artifacts/A1-pilot --resume --stop-after-updates 150
python -m mathlab.evaluate --data data/processed/v1/validation.jsonl \
  --adapter artifacts/A1-step200/best --out results/runs/A1-step200-validation-full
python -m scripts.analyze_predictions results/runs/A1-step200-validation-full \
  --data data/processed/v1/validation.jsonl \
  --out results/runs/A1-step200-validation-full/analysis.json
python -m mathlab.compare results/runs/A1-step50-validation-full \
  results/runs/A1-step200-validation-full \
  --out results/runs/A1-step50-vs-step200-full.json
```

权重快照复制、子集配对分析与证据归档通过一次性 Python 文件操作完成。上述输出目录已存在；复跑应使用新目录并保留旧结果。

| 全部生成准确率 | 141/1,000（14.10%） | 174/1,000（17.40%） |
| 合法且未截断的答案 | 988/1,000 | 1,000/1,000 |
| 基础计算 | 67/334 | 77/334 |
| 混合运算 | 1/333 | 1/333 |
| 应用题 | 73/333 | 96/333 |
| 单步加法 | 0/154 | 1/154 |
| 单步减法 | 0/159 | 1/159 |

| 单步除法 | 140/193 | 169/193 |
| 不含任何除法的表达式 | 0/691 | 4/691（0.58%） |
| 正确且原样保留单步除法分子/分母 | 140 | 169 |

任务分组与运算分组有交叉，不能将表中所有正确数相加。200 步模型剩余 826 题均为可解析但数值错误，格式解析失败、截断、运行错误均为 0。

训练循环累计耗时约 79.0 秒，较前一阶段增加约 50.8 秒，含各段的验证与保存；不包含暂停期间、完整生成评测和每次加载的全部墙钟时间。累计目标 token 为 21,635，非 padding token 为 201,740。MPS 上未使用 CUDA 显存指标，不把空值写成 0 显存。

### 配对比较

同题总分增加 3.3 个百分点，5,000 次配对 Bootstrap、种子 42 的 95% 百分位区间为 **[2.1, 4.6] 个百分点**。39 题由错变对、6 题由对变错，净增 33 题。

单步除法净增 29 题（34 题由错变对、5 题由对变错）；非除法净增 4 题。混合运算总正确数不变，但不是同一题保持正确：前一阶段的正确题变错，另有一道新题答对。

非除法差值为 +0.579 个百分点，探索性子集区间约为 [0.145, 1.158] 个百分点。子集区间未做多重比较调整；所有区间仅覆盖问题抽样，不覆盖训练种子波动。这里是用于配置选择和诊断的验证集，不能当作最终测试或稳定泛化证据。

## 6. 正确样本与局限

下面列出**全部 4 个非除法正确样本**，避免只挑选有利案例：

| 样本 ID | 表达式 | 标准答案 | 模型输出 |
| --- | --- | --- | --- |
| validation_8f289444720682de | 33 - 84 | -51 | 答案：-51 |
| validation_f0c3aa56059b5a8d | 41 * 1 | 41 | 答案：41 |
| validation_63f32bbf2a8fd8ef | 50 * 1 | 50 | 答案：50 |
| validation_5e7f84eb9694f793 | 28 + 6 | 34 | 答案：34 |

两道乘法都是乘以 1，可直接保留另一个操作数。唯一正确混合运算为 `(48 - 85) / 65`，输出 `-37/65`；它不属于单步除法原样输出标记。

这意味着 174 个正确答案中，169 个集中在直接分数输出，其余 5 个中还包括 2 个乘以 1 的简单题。普通加减乘和混合计算仍几乎不可用。更多训练改善了格式稳定性与部分任务分数，但远没有完成一般计算能力增强。

## 8. 下一步

继续无区分地扩展同样训练，暂不能保证解决普通计算问题。下一阶段优先开展**低难度算术的可学习性检查**：先固定一位数加减任务，验证极小训练集能否过拟合，再用未见问题检查泛化。难度、监督形式或注入模块的改变应分开对照，不能同时修改后将收益归因于某一个因素。

当前不进入 GRPO：非除法题的可验证正确率仍极低，需要先建立可靠的监督学习信号。上述下一步尚未执行，应单独立项、固定数据与预算并写新报告。
