# MiniMind-Math：基于高效微调的轻量级数学任务能力增强

> 文档用途：个人执行计划、GitHub 项目说明草稿、Obsidian 项目笔记。
>
> 当前状态：据前序对话，已下载并运行 MiniMind-3；尚未提供数学评测、训练和消融实验的可核查记录。本文中的数据规模、参数组合和时间均为计划，不代表已完成工作或效果承诺。所有结果用“待测”表示。

## 1. 项目定位与范围

**英文名称：** MiniMind-Math: Enhancing Mathematical Reasoning in Small Language Models

**建议仓库名：** `MiniMind-Math-Lab`

面向大模型算法工程师实习，基于 MiniMind-3 Dense 模型开展可验证数学任务的参数高效微调实验。重点展示数据构建、底层模块实现、评测设计、成本分析与可复现实验能力。

前序对话中的个人背景是应用统计硕士，已学习 Transformer、Attention、BPE 等基础知识，接触过 PyTorch，主要开发设备为 MacBook Pro。计划周期为 **6～8 周**，按实际学习与实验进度调整。

### 1.1 核心研究问题

1. 在固定数学数据与训练预算下，微调能否改善原始模型的任务准确率？
2. LoRA 注入 Q/V、Q/K/V/O、Attention + FFN 时，性能与资源消耗如何变化？
3. Rank 的变化是否带来稳定收益？新增参数和训练成本是否值得？
4. 收益能否延伸到未见模板、未见数值范围，而不仅是同分布题目？

### 1.2 任务边界

| 范围 | 任务 | 项目优先级 |
| --- | --- | --- |
| 核心 | 整数四则运算、带括号的混合运算 | 必做 |
| 核心 | 短文本、有限步骤的简单应用题 | 必做 |
| 扩展 | 从文字抽取数学表达式 | 核心完成后加入 |
| 扩展 | 是否调用计算工具、调用格式与执行结果 | 独立评测支线 |
| 进阶 | 基于可验证奖励的 GRPO | 条件满足后选做 |

约 64M 参数仅作为 MiniMind-3 的公开规模描述，实际参数量应从所选权重统计。项目不以奥赛、开放域复杂证明或通用数学能力为目标。合成任务上的提升不能直接推广为真实数学推理能力提升。

**最小完整成果：** 固定评测集 + 数学数据流水线 + 原始模型/官方 LoRA/自定义 LoRA 对照 + 模块与 Rank 消融 + 可复现报告。GRPO、工具调用和展示 Demo 不作为核心项目验收前提。

## 3. 技术路线

```text
固定上游提交、模型权重、Tokenizer 与环境
                    ↓
Baseline 评测：原始模型在固定数学任务上的能力
                    ↓
数学数据生成 → 校验 → 去重 → 分组划分 → 冻结版本
                    ↓
SFT 目标下的官方 LoRA 微调（可选增加全参数 SFT 对照）
                    ↓
扩展 LoRA：非方阵线性层、模块选择、Rank、缩放、Dropout
                    ↓
模块/Rank 消融 → 泛化与错误分析 → 成本比较
                    ↓
可选 GRPO：仅在 SFT 后存在有效奖励信号时开展
                    ↓
代码、配置、逐题预测、报告与简历证据归档
```

**术语说明：** SFT 是监督训练目标；LoRA 是可训练参数的组织方式。LoRA 微调同样可以使用 SFT 目标。“全参数 SFT”与“LoRA-SFT”才是本项目中需要明确区分的训练方案。

## 4. 阶段一：理解代码与建立 Baseline

### 4.1 阅读与版本核验

按固定提交检查以下入口；若目录发生变化，以所选版本实际代码为准。

| 入口 | 需要回答的问题 |

### 4.2 评测程序

计划编写 `evaluation/eval_math.py`，统一负责加载模型、生成答案、提取最终答案、标准化、判分和保存逐题结果。工具调用另设评测入口。

- 先构建 **200～500 道开发烟雾测试题**，用于调通程序、定位格式问题；这些题不作为最终测试集。
- 第 1～2 周完成正式数据版本与测试集冻结，**正式训练前重新运行原始模型 Baseline**。
- 初始主评测采用确定性解码；固定提示词、Chat template、思考开关、生成长度、停止标记、batch 与精度。
- 保留原始输出，判分器版本和异常原因。解析失败、超时、截断都计入分母，并单独统计。
- 用手工可验证的样例检查答案解析器与数学求值器，包括负数、零、分数、括号和非法输出。

每题至少保存：`sample_id`、任务类型、分布划分、标准答案、原始输出、解析答案、是否正确、失败类型、生成 token 数和耗时。

## 5. 阶段二：构建数学任务数据集

### 5.1 规模与任务设计

初始目标为 **8,000 条训练数据、1,000 条验证数据、1,000 条正式测试数据**。这是工作量与实验设计起点，可在正式冻结前调整；不把扩充数据量等同于质量提升。

| 题型 | 示例 | 标注与控制 |
| --- | --- | --- |
| 基础计算 | `125 + 378 = ?` | 程序生成精确答案，按运算与位数分桶 |
| 混合运算 | `(36 + 24) × 5 = ?` | 控制括号深度、运算步数及数值范围 |
| 简单应用题 | 20 个苹果平均分给 5 人，每人几个？ | 模板对应确定表达式，检查单位与歧义 |
| 表达式抽取 | “36 与 24 的和乘 5” | 标注表达式结构，不仅保存计算值 |
| 工具决策 | 是否需要调用计算器，调用参数是什么？ | 加入无需调用和非法参数样本，另设工具协议 |

第一版先使用整数与可精确表示的有理数，限制运算复杂度。若加入小数，在数据协议中明确精度和舍入规则。过程监督可作为后续单独变量；初版采用简短解答和统一最终答案字段，避免一次改变多个因素。

### 5.3 防泄漏与泛化划分

1. 为数学底层问题生成规范键；同一问题的改写、同一表达式的表面变体按组分配，避免跨集合出现。对交换律等等价变体，按事先定义的归一化规则检查。
2. 保留 ID（同分布）测试，并设置模板留出、数值范围留出的 OOD 子集；不同 OOD 机制分开报告。数字、样例和任务名随意更换不能消除结构泄漏。
3. 先定义划分规则，再按规则生成或分配数据；训练集与验证集用于训练和选择配置，测试集用于最终评估。
4. 比对训练、验证、测试的文本哈希与问题键，检查重复和近重复；对题型、难度、答案长度及运算符分布生成摘要。
5. 保存生成代码版本、随机种子、分组规则、文件哈希与数据清单。修改测试题或判分规则必须升版本，并重新计算全部相关 Baseline。
6. 不能声称已排除上游预训练数据污染。若无法审计上游语料，在报告中注明这项限制。

工具求值使用受限表达式解析器、运算白名单和资源限制，不对模型输出直接执行任意代码。若使用外部数据或教师模型生成解答，记录来源、许可、生成配置与复核方式。

## 6. 阶段三：SFT / 官方 LoRA 基线

从同一份已训练基础权重出发开展数学任务微调。核心路线无需重新预训练；全参数 SFT 可作为资源允许时的参考对照。

### 6.1 权重和环境兼容

- 区分 Transformers 模型目录、原生 PyTorch 检查点、LoRA 适配器和训练恢复检查点；它们不能当作同一种输入替换。
- 核对隐藏维度、层数、Attention/KV 头数、词表、Tokenizer、模板及权重键。
- 如需转换，先用少量固定输入比较转换前后的 logits 或生成结果，记录误差与精度；加载告警必须逐项解释。
- 适配器绑定基础权重标识与哈希，避免在不同基础模型上加载同名 LoRA。

### 6.2 先检查训练链路，再扩大实验

- 小 batch 完成 forward、backward、保存、重新加载和推理。
- 验证 LoRA 组中仅目标适配器参与优化；检查梯度、参数变化与 trainable 参数列表。
- 验证只对预定 assistant 目标 token 计算损失，排除 padding；检查答案是否被截断。
- 用极小训练集验证可学习性，再观察验证集损失和任务准确率。训练损失下降不等于测试能力提升。
- 通过验证集选择学习率、训练时长与检查点，选择规则在正式比较前确定。

候选训练配置包括序列长度、每卡 batch、梯度累积、优化步数、学习率与调度、权重衰减、梯度裁剪和数值精度。先测量数据 token 长度，再决定截断长度。

有效 batch 在完整累积步下为：

$$
B_{\mathrm{eff}}=B_{\mathrm{device}}\times N_{\mathrm{devices}}\times N_{\mathrm{accum}}.
$$

同时记录实际训练样本数、非 padding token 数和优化器更新步数，解释末批与末次累积的处理。

### 6.3 命令记录原则

本文不复制前序对话中的训练命令，避免路径、参数与代码版本不一致。正式执行时先核对固定提交中的参数解析、工作目录、加载函数和权重位置，再将**实际成功运行的完整命令**保存到实验记录；需要时在确认环境可用后查看脚本帮助。

## 7. 阶段四：LoRA 模块扩展

### 7.1 已核对的切入点

在上述固定快照中，[上游 LoRA 注入函数](https://github.com/jingyaogong/minimind/blob/f659b55761b754d306bd140573493a6543cafd7f/model/model_lora.py)仅选择输入与输出维度相同的线性层。结合[模型默认 Dense 配置](https://github.com/jingyaogong/minimind/blob/f659b55761b754d306bd140573493a6543cafd7f/model/model_minimind.py)，Q/O 投影为方阵，K/V 与 FFN 投影为非方阵。这是该代码快照和默认配置下的观察；实验必须输出所选模型的实际注入清单，不能仅凭模块名推断。

**待验证假设：** 扩大注入位置可能提升数学任务适配能力，但也增加参数与成本。Q/V、Q/K/V/O 或 Attention + FFN 哪种更有效，需由实验回答。

### 7.2 数学形式

对输入 $x\in\mathbb{R}^{d_{\mathrm{in}}}$，冻结基础权重 $W\in\mathbb{R}^{d_{\mathrm{out}}\times d_{\mathrm{in}}}$，设置：

$$
A\in\mathbb{R}^{r\times d_{\mathrm{in}}},\qquad
B\in\mathbb{R}^{d_{\mathrm{out}}\times r}.
$$

训练时的适配分支为：

$$
h=Wx+b+\frac{\alpha}{r}BA\,\mathrm{Dropout}(x).
$$

其中 $r$ 是 Rank，$\alpha$ 是缩放超参数。评估时关闭 Dropout，可合并为：

$$
W_{\mathrm{merged}}=W+\frac{\alpha}{r}BA.
$$

单个无偏置适配器的可训练参数量为：

$$
P_{\mathrm{LoRA}}=r(d_{\mathrm{in}}+d_{\mathrm{out}}).
$$

以上基于标准 [LoRA 方法](https://arxiv.org/abs/2106.09685)，属于实现扩展与实验研究，不宣称方法原创。

### 7.3 实现目标与检查点

- 支持非方阵 `Linear`，按模块全名或明确后缀选择目标，并打印匹配和排除列表；匹配为空时明确报错。
- 支持 `q_proj`/`v_proj`、`q_proj`/`k_proj`/`v_proj`/`o_proj`，以及加入 `gate_proj`/`up_proj`/`down_proj` 的配置；默认不扩展 embedding 或输出头。
- 支持 Rank、Alpha、Dropout；保存这些元数据、基础权重标识与注入层清单。
- 明确初始化策略；例如 B 初始化为零，使初始适配器增量为零。兼容对照需与官方初始化一致。
- 正确处理设备、dtype、保存加载与权重合并，防止重复注入或重复合并。
- 编写必要的实现测试：非方阵输出形状、零增量等价、基础参数冻结、首步 B 梯度与后续 A/B 更新、保存加载一致、合并前后评估输出在数值容差内一致。

## 8. 阶段五：实验与消融设计

### 8.1 推荐最小实验矩阵

| ID | 方案 | 目标模块 | Rank | 作用 |
| --- | --- | --- | --- | --- |
| A0 | 原始模型 | 无 | — | 无数学微调的 Baseline |
| A1 | 官方 LoRA-SFT | 实际自动匹配清单 | 16 | 上游实现对照 |
| A2 | 自定义兼容 LoRA-SFT | 与 A1 完全一致 | 16 | 排查重构实现差异 |
| A3 | 自定义 LoRA-SFT | Q、V | 16 | 注入位置比较 |
| A4 | 自定义 LoRA-SFT | Q、K、V、O | 16 | 注入位置比较 |
| A5 | 自定义 LoRA-SFT | Attention + FFN | 16 | 扩大注入范围 |
| R1–R4 | 自定义 LoRA-SFT | 验证集选定的一组模块 | 4 / 8 / 16 / 32 | Rank 消融，复用对应已有实验 |
| F0 | 全参数 SFT，选做 | 全参数 | — | 适配能力与成本参考 |
| G0 | GRPO，选做 | 明确训练参数范围 | 按实际配置 | 与其起始 SFT 模型对照 |

A2 的缩放设为 1、Dropout 为 0，并保持基础权重、注入清单、初始化和训练配置一致，用于对齐官方行为。主模块消融也固定缩放和 Dropout；例如令 $\alpha=r$、Dropout 为 0。若另试缩放或 Dropout，将其作为独立消融，避免收益归因混乱。

### 8.2 公平性与结果解释

1. 固定基础权重、数据版本、样本顺序种子、目标 token、有效 batch、优化步数、评测协议和硬件；记录每组实际消耗。
2. 相同 Rank 不代表相同参数量或相同算力。第一轮比较固定训练数据与更新步数，并明确报告参数、时间、显存差异。
3. 若要回答“相近参数预算下哪些模块有效”，另设匹配可训练参数量的 Rank 组合；若回答“相同 GPU 时间下哪个更有效”，另设时间预算实验。无法完全匹配时报告实际差异。
4. 固定一套配置的控制实验与各方案等额调参预算下的最优配置比较分开呈现。选定方案依赖验证集，不依据测试集反复调参。
5. 先单种子筛选，再对关键对照尽量运行至少 3 个训练种子，报告均值与标准差；预算只能支持单次实验时标为探索性结果。
6. 固定模型的题目抽样不确定性与训练种子波动是两件事。可使用按问题组重采样的配对 Bootstrap 分析准确率差值，单独报告区间与重采样协议。
7. 最终测试在方案与检查点选择完成后统一运行。若测试结果已用于下一轮设计，记录该事实，后续确认性结论需要新的留出集。

### 8.3 错误分析

按任务、运算类型、数值位数、括号深度、文本模板及答案长度分析。错误至少区分计算错误、题意/表达式错误、格式或解析失败、截断、工具决策错误、参数错误与执行后回答错误。样例由规则抽样，保留成功和失败案例，避免只展示有利输出。

## 9. 评价指标与测量协议

### 9.1 任务效果

设正式评测共 $N$ 题，规范化后的预测为 $\hat a_i$，标准答案为 $a_i$：

$$
\mathrm{Accuracy}=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}[\hat a_i=a_i].
$$

| 指标 | 定义或用途 |
| --- | --- |
| 最终答案准确率 | 主指标；整数精确比较，有理数先约分，单位按任务协议处理 |
| 分题型/分难度准确率 | 避免总分掩盖短板；各项列出题目数 |
| ID / OOD 准确率 | 同分布、模板留出、范围留出分别报告 |
| 宏平均准确率 | 各预定题型准确率等权平均；同时报告全样本微平均 |
| 解析失败率 | 无法按冻结规则得到合法最终答案的比例 |
| 表达式 Exact Match | 规范化后与参考表达式一致；规范化规则固定 |
| 表达式结构等价率，选做 | 在明确受限语法下判断等价；仅计算结果相同不能证明表达式正确 |
| 验证集目标 token Loss | 训练诊断；不能替代生成式任务准确率 |

若加入浮点任务，提前固定绝对与相对容差：

$$
|\hat a-a|\leq\epsilon_{\mathrm{abs}}+\epsilon_{\mathrm{rel}}|a|.
$$

容差由任务精度要求决定，不能看到结果后放宽。多个最终答案、含糊结论和缺失答案的处理也应事先定义。

工具支线同时报告：是否调用的准确率及 Precision/Recall、格式合法率、工具名/参数正确率、端到端答案准确率、平均调用次数。明确分母为全部题目、需要调用的题目或实际调用次数。**模型独立作答**与**允许计算工具**作为不同轨道，分别评测与比较。

### 9.2 训练与推理成本

$$
\mathrm{TrainableRatio}=\frac{P_{\mathrm{trainable}}}{P_{\mathrm{total}}}\times100\%.
$$

记录总参数和可训练参数；说明分母是否包括适配器、共享权重是否去重。记录峰值显存 allocated/reserved、训练墙钟时间、GPU 小时、训练吞吐（非 padding tokens/s）和存储大小。

推理报告 batch=1 的端到端延迟中位数与 P95、生成 tokens/s，并记录输入/输出长度。统一硬件、精度、KV cache、预热与 GPU 同步方式；评估顺序一致或随机化。分别说明适配器未合并与已合并的推理形态，不混用两种形态得出速度结论。

准确率变化使用百分点：

$$
\Delta_{\mathrm{pp}}=100\times(\mathrm{Acc}_{\mathrm{new}}-\mathrm{Acc}_{\mathrm{base}}).
$$

其中准确率按 $[0,1]$ 取值。若报告相对提升，另写明计算分母；Baseline 为零时相对提升无定义。

## 11. 阶段六：可选 GRPO

### 11.1 启动条件

- 核心 SFT/LoRA 对照与消融已完成，评测与奖励程序通过边界案例检查。
- 对同一训练问题采样多个回答时，有一定比例的组出现奖励差异；并非所有组都全错或全对。
- 有足够预算支付多回答 rollout、训练和验证；明确比较起点、参数范围与额外训练成本。

不满足条件时，先改进数据、降低任务难度或完善监督训练。停留在扎实的 SFT/LoRA 项目同样可以形成完整成果。

### 11.2 奖励与诊断

最小可验证奖励为：

$$
R(y,a)=\mathbf{1}[\mathrm{parse}(y)=a].
$$

格式奖励、部分步骤奖励或工具参数奖励仅作为独立扩展。若使用组合奖励：

$$
R=w_{\mathrm{ans}}R_{\mathrm{ans}}+w_{\mathrm{fmt}}R_{\mathrm{fmt}}+w_{\mathrm{step}}R_{\mathrm{step}},
$$

需记录权重与检查规则，防止只学习格式、重复答案或利用判分漏洞。步骤无法可靠验证时不使用步骤奖励。

对同题的 $G$ 个回答，组内相对优势的一种示意为：

$$
\hat A_i=\frac{R_i-\overline R}{\operatorname{std}(R_1,\ldots,R_G)+\epsilon}.
$$

这仅用于解释组内信号，不是完整 GRPO 目标或某一实现的逐行定义。正式训练需按所选实现核对策略比率、裁剪、KL、mask 和归一化。组内奖励相同会使这一相对奖励优势为零；额外 KL 项等仍可能产生梯度，不能将其等同于整个训练完全无梯度。

记录正确率、平均奖励、零方差组比例、输出长度、KL（若启用）、rollout 吞吐与训练稳定性。比较“起始 SFT 模型”“继续 SFT 的额外预算对照，资源允许时”“GRPO 模型”，防止把额外计算收益全部归因于训练算法。

DPO、蒸馏等不列入本期必做范围。GRPO 使用奖励自动校验，不需要为展示技术广度再强行加入偏好训练。

其中 $t_j$ 为实际计费 GPU 小时，$p_j$ 为下单时单价；存储和网络费用单独记录。预算表填写“预估/实际”两列，筛选实验与重复实验均计入总成本。

## 15. 风险与处理原则

| 风险 | 识别信号 | 处理方式 |
| --- | --- | --- |
| 模型容量或任务难度不匹配 | 简单任务也长期接近无效输出 | 先验证数据、mask 和权重，再分层降低难度；报告能力边界 |
| 合成模板记忆 | ID 提升，模板或范围 OOD 无改善 | 分组留出，按难度报告，不夸大为通用推理增强 |
| 数据/测试泄漏 | 改写题跨集合、测试题参与调参 | 规范键去重、版本冻结、另设确认性留出集 |
| LoRA 改动归因混乱 | 同时改模块、缩放、Dropout 和数据 | 先兼容组，再单因素消融，记录实际参数预算 |
| 训练与推理不一致 | 适配器错配、合并后结果异常 | 固定基础哈希，验证保存加载和合并数值一致性 |
| 数学判分错误 | 正确负数/分数被判错，非法表达式通过 | 边界样例校验，保留原始输出，冻结规则 |
| 奖励无差异或被利用 | 大量零方差组，格式奖励上涨但答案不变 | 降低任务难度，审计奖励，暂缓 GRPO |
| 时间与预算失控 | 大量全组合搜索、重复失败训练 | 优先最小矩阵，短运行估算，关键组复跑后及时收束 |
| 结果不稳定 | 种子间差异大或少数题决定结论 | 重复关键组，报告区间、样本量与探索性限制 |
| 来源与贡献不清 | 无法分辨上游与本人工作 | 保留来源，维护贡献清单，简历只写已完成内容 |
