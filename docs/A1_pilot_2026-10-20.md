## 具体执行了什么

1. 读取已冻结的数据 v1、原始 MiniMind-3 权重和 `configs/official_lora.json`，未改动模型主干、数据、提示词或判分规则。
2. 在 Apple M4/MPS、float32 上调用官方 LoRA 注入函数。实际匹配 8 层的 Q/O 投影，共 16 个线性层，rank=16、alpha=16、dropout=0；基础模型参数冻结，只训练 393,216 个适配器参数。
3. 执行 50 次优化器更新。每次 microbatch=4、累积 4 次，有效 batch=16，共处理 800 条不同训练样本；训练池为 8,000 条。本次不是训练 50 个 epoch，而是第一个 epoch 的前 50/500 次更新。
4. 训练前后各在全部 1,000 条验证题上计算目标 token loss。保存 best/last 适配器与可恢复检查点；best 在 step 0 和 step 50 两个已验证保存点之间选择，本次选中 step 50。
5. 对原始模型与保存后重载的 best 适配器，分别评测完全相同的 24 道验证题，每类 8 道。使用原评测协议：贪心、关闭思考、256-token 上限、精确有理数判分；比较工具已检查基础模型、Tokenizer、数据、题目 ID、设备、精度、解码和判分代码一致。
6. 归档逐题原始输出、配置、环境、模型/数据/源码哈希、训练日志与配对比较。正式 test_id、test_template、test_range 没有用于本次生成评测。

## 实际结果

本轮实际检查包括：50 次更新的 loss 均有限、适配器文件哈希与元数据一致、基础模型身份绑定一致、比较工具的同题同协议校验通过、报告数值/证据/相对链接检查通过。首版的 38 项单元测试属于历史工程验证，本轮没有重新运行这些测试；本轮未修改相应实现。

全验证集的目标 token loss：**3.295360 → 1.183309**。50 次更新中没有非有限 loss。训练循环（含两次验证和保存）约 28.2 秒，不包含模型加载与数据预处理的全部开销。

| 指标 | 原始模型 | 官方 LoRA，50 次更新 |
| --- | --- | --- |
| 生成评测题数 | 24 | 24 |
| 最终答案准确率 | 0/24（0%） | 3/24（12.5%） |
| 合法且未截断的最终答案 | 0/24 | 24/24 |
| 格式解析失败 | 12/24 | 0/24 |
| 生成截断 | 12/24 | 0/24 |
| 解析成功但数值错误 | 0/24 | 21/24 |
| 运行错误 | 0/24 | 0/24 |
| 基础计算准确率 | 0/8 | 2/8 |
| 混合运算准确率 | 0/8 | 0/8 |
| 应用题准确率 | 0/8 | 1/8 |

合法答案率按本项目判分器接受整数/有限小数/有理数的规则计算。预测数字合法不代表答案正确。

输出由长篇解释变为简短最终答案，因此端到端延迟中位数从约 5.40 秒变为 0.18 秒；这两个值对应的生成长度明显不同，不能据此当作相同输出长度下的速度消融结果。

## 结论与下一步

当前最明确的进展是输出格式和长度控制：模型已经可以稳定给出可判分的简短答案。数值计算仍是主要问题，混合运算尚未答对；loss 下降与格式改善不能直接等同于数学推理能力提升。

24 题上的准确率变化为 +12.5 个百分点，5,000 次配对 Bootstrap 的 95% 百分位区间为 **[0, 25] 个百分点**，包含零。此区间只表示这批问题的抽样不确定性，不覆盖训练种子波动；验证题数量也不足以确认泛化收益。

下一步先扩大验证样本、单独统计非除法计算的表现；继续训练时保持数据和协议不变，以分辨训练预算是否足够。若基础算术仍无法学习，再开展低难度数据的可学习性检查或模块对照。当前不进入 GRPO。

本次完整证据见 [结果目录](../results/evidence/2026-10-20-A1-pilot)，执行命令见其中的 [commands.txt](../results/evidence/2026-10-20-A1-pilot/commands.txt)。

适配器位于本地 `artifacts/A1-pilot/best/adapter.pt`，约 1.58 MB；恢复检查点约 4.76 MB。这些权重与恢复状态继续由 .gitignore 排除，未纳入结果归档。
