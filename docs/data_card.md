# 数学数据 v1

程序生成中文有限模板，标签由 Python Fraction 精确计算，不含教师模型生成文本和外部题库。题型是基础四则、3 种有限结构的混合运算、4 类简单单步应用题；输出仅包含 `答案：<最简整数或分数>`，不提供长思维链。

| 集合 | 数量 | 用途 |
| --- | --- | --- |
| train | 8000 | 训练 |
| validation | 1000 | 配置与检查点选择 |
| test_id | 1000 | 同分布最终评估 |
| test_template | 300 | 新表述/新场景的模板留出 |
| test_range | 300 | 基本操作数在 1000～9999 的范围留出 |
| smoke | 240 | 开发调试，不计入正式结果 |

每个集合尽量均分 arithmetic/mixed/word。ID、train、validation、smoke 的表达式叶子操作数为 1～99。除法可能产生真分数，减法可能为负数；应用题减法保证数量非负，除法采用可分割的绳长/道路长度，避免“半个不可分物品”的歧义。范围 OOD 控制的是叶子数，运算结果可能远大于 9999。

规范问题键对 AST 中加法、乘法展平并排序，消除相应交换律/结合律变体；减法和除法保留顺序。所有划分共享已用键集合，应用题与计算题的同一底层表达式也禁止跨集合重复。还检查样本文本和 ID 重复。不是完整代数等价判定，例如 `2+2` 与 `2*2` 不被当作相同问题；相同答案可以合法出现于多个集合。

模板 OOD 只考察措辞/场景变化，混合算术结构仍属训练中见过的类型，不能宣传为结构推理泛化。全局去重使各集合并非完全独立同分布的随机抽样。先采训练问题再拒绝重复生成其他集合会轻微改变后续分布；报告时保留此限制。

每条中间数据包含 ID、task、template_id、problem_key、split、distribution、expression、answer、conversations 和 generator_version。`train_sft.jsonl`/`validation_sft.jsonl` 是仅含 conversations 的上游格式导出，不能当成带元数据的评测输入。本项目训练器直接读中间数据，保留 ID 便于报错。

manifest 保存生成器版本、种子、范围规则、代码哈希和各 JSONL 哈希。生成器拒绝覆盖现有目录。训练和评测入口都会重新审计数据并验证冻结哈希。无法审计上游预训练语料，不能声称彻底排除预训练污染；合成算术结果也不能推广为通用数学推理能力。
